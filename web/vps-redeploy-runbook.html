00 Sebelum mulai

Pastikan agent Claude Code di VPS punya akses: git, Node 18+, dan service user yang menjalankan app. Ganti semua nilai <di-dalam-kurung> dengan milik Anda. Pastikan ada backup database sebelum db push.

Wajib — sekali jalan Jalankan perintah rotasi secret di Langkah 5. Secret lama (LICENSE_SIGNING_SECRET yang hardcoded) sudah bocor di git history — tidak boleh dipakai lagi. Tanpa rotasi, kebocoran tetap aktif meski kode diperbarui.

01 Akses & hentikan service

SSH ke VPS, masuk ke direktori app, hentikan process manager supaya build tidak konflik dengan file yang sedang di-serve.

$
ssh <user>@<vps-ip>
$
cd </path/to/app>

Hentikan sesuai process manager yang Anda pakai. Contoh PM2:

$
pm2 stop vortx-web # ganti nama process sesuai Anda

Atau kalau pakai systemd:

$
sudo systemctl stop vortx-web

02 Backup database

Jangan dilewati

prisma db push mengubah skema api_keys (kolom key jadi nullable, kolom baru key_hash). Backup dulu.

$
pg_dump "$DATABASE_URL" -F c -f ~/vortx_backup_$(date +%Y%m%d_%H%M).dump
$
ls -lh ~/vortx_backup_*.dump # verifikasi file ada >0

03 Pull branch Production

Tarik branch Production terbaru yang sudah berisi security-fix.

$
git fetch origin
$
git checkout Production
$
git pull origin Production
$
git log --oneline -3 # konfirmasi f889f04 ada di atas
Verifikasi merge HEAD harus f889f04. Kalau bukan, berarti push dari lokal belum sampai — jalankan dari mesin lokal: git -C /c/Project/VortXLabs1.2 push origin Production lalu ulangi git pull di VPS.

04 Pindahkan upload lama ke private/

File upload kini diserve lewat route auth (/api/admin/files/download), bukan static lagi. Pindahkan folder lama supaya file kredensial tidak exposed langsung oleh reverse proxy.

$
cd </path/to/app>/web
$
mkdir -p private
$
[ -d public/uploads ] && mv public/uploads private/uploads && echo "moved" || echo "sudah kosong / sudah ada"
$
ls private/uploads/data 2>/dev/null | head -3 # cek isinya ikut pindah
Nginx / reverse proxy

Pastikan TIDAK ada directive yang static-serve /private/. Hanya public/ boleh di-expose sebagai root. Contoh blok yang benar hanya mendelegasikan ke Next:

location / {
  proxy_pass http://127.0.0.1:3000;
  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-Proto $scheme;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}

Jangan tambahkan root .../public yang menangkap /private.

05 Rotasi LICENSE_SIGNING_SECRET (wajib)

Generate secret baru, tulis ke .env. Jangan commit file .env.

$
NEW_SECRET=$(openssl rand -hex 32)
$
echo "LICENSE_SIGNING_SECRET=$NEW_SECRET" >> web/.env
$
grep -c LICENSE_SIGNING_SECRET web/.env # harus >=1

Catat secret ini di password manager. Lisensi app lama yang ditandatangani pakai secret lama akan gagal validasi — regenerate via panel admin bila perlu.

06 Update dependency & generate Prisma client

$
cd </path/to/app>/web
$
npm ci # install persis dari lockfile
$
npx prisma generate

07 Apply skema ke database

$
npx prisma db push

Akan menambah kolom key_hash (unique) + index, membuat key nullable. Data lama tidak hilang — key plaintext lama tetap di kolom key, dual-lookup aktif.

08 Build

$
npm run build

output: "standalone" menghasilkan .next/standalone (server.js mandiri) + .next/static. Untuk deploy standalone, salin hasilnya keluar:

# setup standalone (sekali, lalu tiap rebuild refresh)
mkdir -p .next/standalone/public
cp -r public/* .next/standalone/public/ 2>/dev/null || true
mkdir -p .next/standalone/private
cp -r private/* .next/standalone/private/ 2>/dev/null || true
cp -r .next/static .next/standalone/.next/static

09 Jalankan kembali service

Contoh PM2 (ganti NODE_ENV dan port sesuai setup Anda):

pm2 start .next/standalone/server.js \
  --name vortx-web \
  --env production \
  -- 3000

# atau restart kalau sudah pernah didaftarkan:
pm2 restart vortx-web

pm2 save

systemd alternatif — pastikan WorkingDirectory = .next/standalone dan EnvironmentFile = .env.

10 Verifikasi post-deploy

  • App live: curl -sI https://vortxlab.my.id | head -1 → 200/3xx
  • HSTS header ada: curl -sI https://vortxlab.my.id | grep -i strict-transport
  • /private/ tidak accessible: curl -sI https://vortxlab.my.id/private/uploads/data/x.conf → 404 (bukan 200)
  • Webhook Cashi masih receive (test callback dari dashboard Cashi)
  • Login brute-force: coba login salah 5× → akun terkunci 15 menit
  • Register password <8 char ditolak (400)
  • API key lama masih jalan (dual-lookup) — client tidak perlu update dulu

11 Regen API key (opsional tapi disarankan)

Legacy key plaintext masih di kolom key. Kalau DB bocor, key itu kelihatan. Regen via UI dashboard untuk migrasi ke hash-only, lalu update client.

  1. Login dashboard → tab API Key → Re-generate Key
  2. Salin key baru sk-vrtx-… (hanya tampil sekali)
  3. Update semua client/bot pakai key baru
  4. Setelah yakin semua bermigrasi, bisa npx prisma db execute untuk null-kan kolom key sisa legacy

Rollback (jika rusak)

# 1. restore DB
pg_restore -d "$DATABASE_URL" -F c -c ~/vortx_backup_<timestamp>.dump

# 2. kembalikan commit sebelum security-fix
git checkout Production
git reset --hard 6d1a939
npm ci && npx prisma generate && npm run build
pm2 restart vortx-web

# 3. kembalikan folder upload ke public/ bila perlu
mv private/uploads public/uploads
